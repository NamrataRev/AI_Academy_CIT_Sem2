# Quality Criteria

---

You submit an assignment. You get it back with a low mark.

You are confused. You answered every question. You wrote clearly. You submitted on time. But the feedback says: "answers too vague, examples missing, format incorrect."

You did not fail because you were wrong. You failed because your answers did not meet the criteria — criteria you did not fully understand when you were writing.

A context package can fail the same way. It is present. It is complete on the surface. But the responses it produces are not good enough — because the package was never evaluated against clear quality criteria.

Quality criteria define what a good context package actually looks like. Not good in the abstract — measurable, testable good.

---

## The Four Quality Criteria

**Consistency** — does the package produce the same quality of response across different inputs?

A context package that works well for easy questions but drifts on harder ones is not consistent. A good package produces reliable output across the full range of inputs it will encounter — simple questions, complex questions, edge cases, and unexpected phrasings.

Test: run ten different inputs. If the quality varies significantly, the package is inconsistent. Find which role is causing the variation — usually Authority (wrong calibration) or Constraint (not specific enough).

**Accuracy** — does the package produce responses that are correct for the audience and context?

Accuracy is not just factual correctness. A response can be factually accurate and still inaccurate for the context — using the wrong level, the wrong vocabulary, the wrong depth for the audience defined in Metadata.

Test: check responses against the Metadata. If a response uses vocabulary not yet introduced in the course, or explains a concept at the wrong level, it fails the accuracy criterion even if every fact in it is correct.

**Format compliance** — does every response follow the structure and format defined in the Rubric?

This is the most measurable criterion. The Rubric says: analogy, definition, use case — in that order. Every response should follow this. If responses vary in structure, the Rubric is not working.

Test: check ten responses against the Rubric criteria mechanically. Is the analogy present? Is it first? Is the definition present? Is the use case present? How many of the ten pass all criteria?

**Edge case handling** — does the package behave sensibly when inputs are unusual, ambiguous, or outside the defined scope?

A student asking about a topic not yet covered. A question phrased in an unusual way. A request that partially falls within scope and partially outside it. These are edge cases — and how the package handles them reveals how robust it really is.

Test: deliberately ask questions at the boundary of the Metadata scope. If the package handles them gracefully — redirecting clearly when out of scope, adapting appropriately for unusual phrasings — it passes. If it produces confident wrong answers or silently ignores the constraint, it fails.

---

## Using the Criteria

These four criteria give you a structured way to evaluate any context package — yours or someone else's.

Before testing, decide: what does passing look like for each criterion? Write this down. "Consistency: 9 out of 10 inputs produce responses within the rubric structure." "Format compliance: all three rubric elements present in every response."

Then test. Then score. The criteria turn a subjective question — "is this context package good?" — into a measurable one — "did it pass these four tests?"

---

## Quick Recap

- Quality criteria make context package evaluation measurable rather than subjective
- Four criteria: consistency (same quality across inputs), accuracy (right for the audience and context), format compliance (follows the Rubric every time), edge case handling (sensible behaviour at the boundaries)
- For each criterion: define what passing looks like before testing, then test, then score
- A context package that passes all four criteria is reliable — one that fails any of them has a specific, diagnosable problem
